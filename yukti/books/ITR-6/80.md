# The book of Schedule 80-IA / 80-IB / 80-IE — profit-linked deductions · ITR-6, A.Y. 2026-27

Read row by row from the utility's **80** sheet (129 rows of content, with many
hidden sub-clause rows) and confirmed against the CBDT ITR-6 schema's three
blocks **`Schedule80_IA`, `Schedule80_IB`, `Schedule80_IC`**. Every clause,
label, formula and cross-reference below is the department's own.

---

## 1 · Purpose — the undertaking-by-undertaking profit-linked deductions

The "80" sheet holds **three separate profit-linked deduction schedules** stacked
on one worksheet, each computing a total that flows to Schedule VI-A Part C:

| Sheet block | Sheet heading | Schema block | Feeds VI-A |
|---|---|---|---|
| **Schedule 80-IA** (rows 4–25) | Deductions under section 80-IA | `Schedule80_IA` | Part C item e (80IA) |
| **Schedule 80-IB** (rows 27–81) | Deductions under section 80-IB | `Schedule80_IB` | Part C item h (80IB) |
| **Schedule 80-IE** (rows 83–129) | Sch 80IE Deductions under section 80-IE | `Schedule80_IC` | Part C item j (80IE) |

Each block is a list of eligible **undertakings**, grouped by the sub-clause of
the section they qualify under; each group carries a location/description code and
one or more amount rows, and each block ends in a computed total.

The sheet opens with a governing note (C3): *"(Note: If no entry is made in first
row then other rows will not be considered)"* — the first undertaking row of a
group must be filled for the rest to count.

**Schema-name inconsistency to flag:** the sheet's third block is labelled
**Schedule 80-IE**, but the schema block that backs it is named **`Schedule80_IC`**
(section 80-IE succeeded and absorbed the old 80-IC special-category-states
deduction; the JSON kept the older `_IC` name). The VI-A row that reads it is
item j *"80IE (b of Schedule 80-IE)"* whose allowed key is `Section80IC`. Build
80-IE data into the `Schedule80_IC` block.

## 2 · Schedule 80-IA (rows 4–25) → `Schedule80_IA`

`Sch80SectionCode` identifies the block. Three **visible** sub-clause groups map
to schema objects; two sub-clauses are **hidden** and not built.

| Row | Letter | Sub-clause label | State | Schema object |
|---|---|---|---|---|
| r5 | a | Deduction in respect of profits of an enterprise referred to in section 80-IA(4)(i) [Infrastructure facility] | visible | `DeductUs80_IA_4_i` |
| r9 | b | Deduction in respect of profits of an undertaking referred to in section 80-IA(4)(ii) [Telecommunication services] | **hidden** | — (no schema leaf) |
| r13 | c | Deduction in respect of profits of an undertaking referred to in section 80-IA(4)(iii) [Industrial park and SEZs] | **hidden** | — (no schema leaf) |
| r17 | b | Deduction in respect of profits of an undertaking referred to in section 80-IA(4)(iv) [Power] | visible | `DeductUs80_IA_4_iv` |
| r21 | c | Deduction in respect of profits of an undertaking referred to in section 80-IA(4)(v) [Revival of power generating plant] | visible | `DeductUs80_IA_4_v` |
| r25 | d | Total deductions under section 80-IA (a + b + c) | computed `H25 = SUM(...)` | `TotSchedule80_IA` |

The visible lettering **a, b, c** re-uses the letters because the hidden
(4)(ii) telecom and (4)(iii) industrial-park groups are skipped; on screen
a = (4)(i), b = (4)(iv), c = (4)(v). Rule **A823** — Total under 80-IA = a + b + c.

Each visible group carries:
- `Sch80LocOrDescCode` — the location/description code for the undertaking,
- `Sch80DeductAmtDtls[]` — a repeatable list of amount rows, each with
  `DeductAmountSec80` (the deduction amount for that undertaking).

The sheet shows the undertaking rows as `Undertaking 1`, `Undertaking 2` (col F,
`CONCATENATE("Undertaking ",E6)`), addable per group.

## 5 · The common shape of every group

Across all three schedules, an eligible-undertaking group is the same object:

| Field | Schema leaf | Note |
|---|---|---|
| Section code | `Sch80SectionCode` | one per schedule block (IA / IB / IE) |
| Location / description code | `Sch80LocOrDescCode` | one per sub-clause group |
| Amount detail rows | `Sch80DeductAmtDtls[]` | **repeatable** — one per undertaking |
| Deduction amount | `Sch80DeductAmtDtls[].DeductAmountSec80` | integer ≥ 0 |
| Block total | `TotSchedule80_IA` / `TotSchedule80_IB` / `TotSchedule80_IC` | computed |

`Sch80SectionCode` and `Sch80LocOrDescCode` are plain code strings (no enum on
the sheet — the sheet has **no dropdowns**; the codes are derived from the
sub-clause the row sits under). There are **no data-validation dropdowns** on the
"80" sheet.

## 6 · Cross-sheet feeds

| Direction | What | Where |
|---|---|---|
| **In** | eligible-profit amounts per undertaking | typed on this sheet |
| **Out** | `TotSchedule80_IA` | Schedule VI-A Part C item **e (80IA)** — `IA80.TotSchedule80_IA` |
| **Out** | `TotSchedule80_IB` | Schedule VI-A Part C item **h (80IB)** — `IB80.TotSchedule80_IB` |
| **Out** | `TotSchedule80_IC` | Schedule VI-A Part C item **j (80IE)** — `IC80.TotSchedule80_IC` |

Rules: **A823** — 80-IA total = a + b + c; **A828** — the 80-IA value in VI-A
(Sl. No. 2e) cannot exceed the Schedule 80-IA total; **A829** — 80-IA cannot be
claimed at VI-A 2e without filling Schedule 80-IA.

---

## 7 · What is mandatory (schema `required`)

- `Schedule80_IA` requires `Sch80SectionCode`, the three groups
  `DeductUs80_IA_4_i`, `DeductUs80_IA_4_iv`, `DeductUs80_IA_4_v`, and
  `TotSchedule80_IA`. Each group requires `Sch80LocOrDescCode`; each amount row
  requires `DeductAmountSec80`.
- `Schedule80_IB` requires `Sch80SectionCode`, the four groups
  (`DeductMinOilUs80_IB_9_Und`, `DeductHousUs80_IB_10_Und`,
  `DeductFruitVegUs80_IB_11A_Und`, `DeductFoodGrainUs80_IB_11A_Und`) and
  `TotSchedule80_IB`, each group with `Sch80LocOrDescCode` and each amount row
  with `DeductAmountSec80`.
- `Schedule80_IC` requires `Sch80SectionCode`, `DeductInNorthEast` (with its eight
  state groups, each `Sch80LocOrDescCode` + `DeductAmountSec80`, and
  `TotDeductInNorthEast`) and `TotSchedule80_IC`.

The `Sch80DeductAmtDtls` arrays themselves are optional (present when the group is
used); the amount within a present row is required.

---

## 8 · What repeats and what does not

| Where | Repeatable? |
|---|---|
| Undertaking amount rows (`Sch80DeductAmtDtls`) in every group | **yes** — addable per group |
| The sub-clause groups | fixed set per schedule (only the visible ones) |
| The eight North-East state groups | fixed — Assam … Sikkim |
| Block totals and the NE sub-total | one figure each — computed |

---

## 9 · What ITR-6 has here that ITR-2 does not

ITR-2 has **none of this** — the section 80-IA / 80-IB / 80-IE profit-linked
deductions are business/company reliefs and were confirmed absent (hidden) in the
ITR-2 utility. On ITR-6 they are three live schedules, undertaking by undertaking,
feeding Part C of Schedule VI-A. This whole sheet is a company-return schedule
with no individual-return counterpart.

---

## 10 · What this means for the build

1. **Three schedules on one screen**, each a set of visible sub-clause groups;
   build only the visible groups (three for IA, four for IB, the North-East
   breakdown for IE) and their totals.
2. **Do not build any hidden sub-clause** — telecom/industrial-park under IA; the
   seven lapsed reliefs under IB; the old Sikkim/HP/Uttaranchal rows under IE.
   None has a schema leaf; log each as excluded (*hidden sub-clause, no schema key*).
3. **Every group is the same object** — a location/description code plus a
   repeatable list of undertaking amount rows; the block totals are computed and
   green.
4. **No dropdowns on this sheet** — the section/location codes are derived from
   the group, not chosen from a list.
5. **Route the three totals to VI-A Part C** (e / h / j) and enforce A823 / A828 /
   A829; write **80-IE data into the `Schedule80_IC` block** (name mismatch noted).
