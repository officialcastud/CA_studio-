## The shape

Schedule 80P is a **single fixed matrix** — one row per sub-clause of s.80P(2), no repeats. Header `[C3]` = **"Schedule 80P"**, `[E3]` = **"Deductions under section 80P"**.

Three data columns (header row 4) and 13 activity rows (rows 5–17) plus one Total row (row 18):

- Column `[F4]` = **"Nature of Business Code (Only in relation to Co-operative societies Activities)"** — a dropdown (single-select) → schema key `…Code` (see items). Enum range name `Sch80P_NOBCode`.
- Column `[G4]` = **"Income"** — integer input → schema key = the un-suffixed base key (e.g. `Sec80P2ai`).
- Column `[H4]` = **"Amount eligible for deduction"** — integer input → schema key = the `…Amt` key (e.g. `Sec80P2aiAmt`). This is the deduction that flows to Schedule VI-A.

Column **L is hidden** (cols 11–16384 hidden in the worksheet); `L5` holds a computed cap helper (see rules). No data **rows** are hidden — every row 5–18 is visible.

Each activity row is three schema leaves under the flat parent object `Schedule80P`; the Total row is the two required keys `Sec80PTotal` (income total, `[G18]`) and `Sec80PTotalAmt` (amount-eligible total, `[H18]`).

## The rules the sheet computes (with cell references)

- **Income total** — `[G18]= MAX(0,SUM(G5:G17))` → `Sec80PTotal`.
- **Amount-eligible total** — `[H18]= IF(MID(sheet1.ReturnFileSec,1,2)="12",0,IF(bacValue=1,0,IF(MID(sheet1.ReturnFileSec,1,2)="12",0,MAX(0,SUM(H5:H17)))))` → `Sec80PTotalAmt`. i.e. total = `MAX(0,SUM(H5:H17))`, **but forced to 0** when (a) the return is filed u/s 139(9)/section beginning "12" (`ReturnFileSec` starts "12") or (b) **new tax regime is opted** (`bacValue=1`). Matches rules.json n641: *"Deduction u/s 80P cannot claimed if New Tax regime has been opted for"*.
- **VI-A flow** — `scvia.Section80P = MAX(0,Sch80P.Total)` and `scvia.Section80P_Calc = MIN(Sch80P.Total)*1` (`vba_text.txt` line 716), where `Sch80P.Total = H18`. So the s.80P deduction in Schedule VI-A (Sl.No. 2n) is `Sec80PTotalAmt`.
- **Interest/Dividend cap helper (hidden `L5`)** — `[L5]= MIN((PL.Dividends+PL.InterestInc),(busipofincl.IncOfCurYrAfterSetOffBFLosses2+MIN(othsrcincl.IncOfCurYrAfterSetOffBFLosses5,(os.DividendGross+os.InterestGross_a+os.InterestGross_b))))`. This caps the Sl.No.11 [80P(2)(d)] eligible amount. Matches rules.json n630–631: *"Sl.no.11 under column 'Amount eligible for deduction' should not be more than sum of Sl.No. (1a + 1bi+ 1bii) of Schedule OS + 5(ii) and 5xiii of bfla subject to interest and dividend declared in P&L"*.
- **Per-row: eligible amount ≤ income** — VBA (`vba_text.txt` 21929–21941, "Deduction cannot exceed value at income column"; rules.json n643: *"eligible amount of deduction claimed cannot be more than income disclosed in schedule 80P for each row"*). i.e. `H(row) ≤ G(row)`.
- **Sl.No.9 [80P(2)(c)(i)] cap Rs.100000** — schema `Sec80P2ciAmt maximum 100000`; VBA 21937: *"cannot exceed Rs.100000"*; rules.json n632–633: *"deduction cannot be more than Rs 100000 or non-speculative and non-specified business income and non presumptive income"*.
- **Sl.No.10 [80P(2)(c)(ii)] cap Rs.50000** — schema `Sec80P2ciiAmt maximum 50000`; VBA 21939: *"cannot exceed Rs.50000"*; rules.json n633: *"deduction claimed under Sec.80P(2)(c)(ii) at Sl.No.10 cannot be more than Rs 50000"*.
- **Sl.No.1–7 [80P(2)(a)(i)–(vii)] cap** — rules.json n636: *"deduction u/s 80P(2)(a)(i) to (vii) cannot be more than non speculative and non specified business income and non presumptive income"*.
- **Sl.No.8 [80P(2)(b)] cap** — rules.json n637: *"deduction u/s 80P(2)(b) cannot be more non speculative and non specified business income and non presumptive income"*.
- **Sl.No.12 [80P(2)(e)] basis** — rules.json n634: *"deduction under section.80P(2)(e) at Sl.No.12 can be claimed on rental income included in gross total income"*.
- **Sl.No.13 [80P(2)(f) Others] cap** — rules.json n635 and VBA 21971: allowed **only when Gross total income ≤ Rs.20000** (`Sheet7.Range("8b.GrossTotalIncome") > 20`… i.e. > 20000 blocks it) *"and to the extent of Interest income in Schedule OS and Sl. No. 4 of Schedule HP"*.
- **Total ≤ sum of rows** — rules.json n638–639: *"Total of deduction at Sl.No.14 is not less than or equal to the sum of deductions claimed at Sl.No.1 to Sl.No.13"*.
- **Code must match the row's own clause** — rules.json n640–641: 80P(2)(a)(i) requires code **23001**, (a)(ii)→23002, (a)(iii)→23003, (a)(iv)→23004, (a)(v)→23005, (a)(vi)→23006, (a)(vii)→23007, (b)→23008, (c)(i)→23009, (c)(ii)→23010, (d)→23011, (e)→23012, (f)→23013 ("can not be claimed for the business code selected Other than …"). VBA `Mid(…,1,5)` compares the 5-digit code prefix.
- **Code ↔ nature-of-business** — rules.json n638: *"Business code selected in 'Schedule 80P' is not matching with the 'Business code' selected in schedule 'nature of business'"*.
- **Eligibility (who can claim)** — rules.json n631–632, 653–654: allowed **only to** *"Primary Agricultural Credit Society / Primary Co-operative Agricultural and Rural Development Bank / Other Co-operative Society"*, and *"cannot be claimed from income offered under section 44AD"*.
- **Mandatory-fill link** — rules.json n642: *"To claim deduction u/s. 80P, it is mandatory to fill schedule 80P & P&L a/c"*; n666: *"Deduction u/s 80P claimed in 'Schedule VI-A' at sl.no.2n but 'Schedule 80P' is not filled!"*.

## What repeats and what is one figure

**Nothing repeats.** The schedule is a fixed 13-activity matrix + one Total row — no add-a-row table. Each of the 13 rows is one code + one income + one amount figure; the Total row is two computed figures (`Sec80PTotal`, `Sec80PTotalAmt`).

## Mandatory

Schema `required` on block `Schedule80P`: **`Sec80PTotal`** and **`Sec80PTotalAmt`** (both computed totals). No per-row key is individually required by the schema; per-row code/income/amount become effectively mandatory only when a row is used (code must match the clause, amount ≤ income). The whole schedule is mandatory to fill when s.80P is claimed in Schedule VI-A (rules.json n642, n666).

## Hidden rows — not built

**None.** No worksheet data row (5–18) is hidden. Column **L is a hidden helper column** (`L5` = the 80P(2)(d) interest/dividend cap helper, see rules) — it is not a schema leaf and is not an input; do not build it as an editable cell.

## What this means for the build

- Build a **fixed 13-row + total** matrix, not a repeating table. Per row: a code dropdown (F), an income input (G), an amount-eligible input (H).
- Wire each row to its three schema keys exactly as the items table (F→`…Code`, G→base key, H→`…Amt`). Totals: `Sec80PTotal = MAX(0,SUM(G5:G17))`, `Sec80PTotalAmt = new-regime/12-filed ? 0 : MAX(0,SUM(H5:H17))`.
- Enforce: `H(row) ≤ G(row)`; row-9 amount ≤ 100000; row-10 amount ≤ 50000; row code prefix must equal the clause's fixed code (23001…23013 in row order); zero the whole deduction when `bacValue=1` (new regime) or `ReturnFileSec` starts "12".
- Push `Sec80PTotalAmt` (H18) to Schedule VI-A `scvia.Section80P` (Sl.No.2n); it is `MAX(0, total)`.
- The code dropdown stores the **5-digit prefix** in the export (`23001`…`23013`), though the UI shows the full "code-label" string.
