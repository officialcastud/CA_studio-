# Schedule 80G — Donations entitled for deduction under section 80G

Form: **ITR-5**, A.Y. 2026-27. Sheet: **80G**. Section: `ded`. Block: **Schedule80G**.
Source: `python tools/dump.py --form ITR-5 --sheet "80G"` (rows / `--formulas` / `--dropdowns "80G"`) and `--schema Schedule80G` / `--leaves Schedule80G`; full (untruncated) formulas read from `sources/ITR-5/ITR5_AY_2026-27_V1.4.xlsm` (sheet `80G`); rules from `books/ITR-5/rules.json` (n 596–612, 4595); named ranges from `books/ITR-5/sheet_map.json`; validator/auto-populate text from `sources/ITR-5/vba_text.txt`.

## The shape

Schedule 80G is **four donee tables (A / B / C / D)**, each a repeating list of donee rows, plus a per-table Total row, and one grand-Total row (E). The header `[F3]` reads (verbatim): **"Details of donations entitled for deduction under section 80G (Please read NOTE below)"**.

The four buckets differ only by the deduction rate and whether the donation is subject to the qualifying limit (10% of adjusted total income):

| Sheet letter | Table label `[D..]` | Rate | Qualifying limit | Utility named range | Schema object |
|---|---|---|---|---|---|
| **A** (`[C4]`) | Donations entitled for 100% deduction without qualifying limit | 100% | No | `Per10080G` | `Don100Percent` |
| **B** (`[C16]`) | Donations entitled for 50% deduction without qualifying limit | 50% | No | `PerNO5080G` | `Don50PercentNoApprReqd` |
| **C** (`[C28]`) | Donations entitled for 100% deduction subject to qualifying limit | 100% | Yes | `PerYES10080G` | `Don100PercentApprReqd` |
| **D** (`[C40]`) | Donations entitled for 50% deduction subject to qualifying limit | 50% | Yes | `Per5080G` | `Don50PercentApprReqd` |
| **E** (`[C52]`) | Total Donations (A + B + C + D) | — | — | — | `TotalDonationsUs80G*` (schedule-level totals) |

(Utility→schema mapping confirmed by the Total formulas: `[L12]=SUM(Per10080G.DonationAmt)` for A, `[L24]=SUM(PerNO5080G.DonationAmt)` for B, `[L36]=SUM(PerYES10080G.DonationAmt)` for C, `[L48]=SUM(Per5080G.DonationAmt)` for D.)

Each donee row splits the donation into **cash vs other mode** (`[L6]` "Donation in Cash", `[M6]` "Donation in other mode", `[N6]` "Total Donation") and computes an **Eligible Amount** in column O. The book layout per table:
- Header row (A: `[E5..Q5]`, B: `[E17..Q17]`, C: `[E29..Q29]`, D: `[E41..Q41]`).
- Sub-header row A: `[L6]/[M6]/[N6]` (repeated at B `[L18..N18]`, C `[L30..N30]`, D `[L42..N42]`).
- Four visible donee rows each (A: rows 7–10, B: 19–22, C: 31–34, D: 43–46) — a repeat list (add-row), not a fixed count.
- Total row (A: row 12 "Total A", B: row 24 "Total B :", C: row 36 "Total C :", D: row 48 "Total D").
- Grand total E: row 52 "Total Donations (A + B + C + D)".
- Note `[C53]`: **"Note : In case of Donee is Government and PAN is not available then use \"GGGGG0000G\" as PAN."**

Row 3 also carries three **hidden-column helper values** used by the qualifying-limit maths: `[S3]` label `C_Eligible` (value in `[T3]`), `[U3]` label `D_Eligible` (value in `[V3]`), `[W3]` label `QualifyingAmount80G` (value in `[X3]`).

## The rules the sheet computes (with cell references)

**Total Donation per row (N) = Cash + Other mode.**
- `[N7]= SUM(L7:M7)` (pattern N7:N10, N19:N22, N31:N34, N43:N46). Matches rules 602–605: *"In Sch 80G, Total Donation at point A/B/C/D should be equal to the sum of Donation in Cash and Donation in other mode."*

**Cash over Rs.2000 is disallowed (`IF(L>2000,0,L)`)** in every eligible-amount formula — matches rules 598–601 (*"at Sl No A/B/C/D, Amount donated in cash more than Rs. 2000 will not be eligible for 80G deduction"*) and VBA (`vba_text.txt`, change 24.01.2023.103.80G.02C): *"If Donation in cash is more than Rs. 2000, 80G Deduction is not allowed"*.

**Eligible Amount (O) — per table:**
- **A (100%, no limit):** `[O7]= MIN(VALUE(SUM(IF(L7>2000,0,L7),M7)),Total_Income)` → eligible = min( (cash≤2000)+other , Total_Income ).
- **B (50%, no limit):** `[O19]= ROUND(MIN(VALUE(SUM(IF(L19>2000,0,L19),M19))/2,Total_Income),0)` → half the eligible donation, capped at Total_Income.
- **C (100%, with limit):** `[O31]= ROUND(MIN(MIN(VALUE(SUM(IF(L31>2000,0,L31),M31)),Total_Income),QualifyingAmount80G),0)` → capped at Total_Income **and** the qualifying limit `QualifyingAmount80G`.
- **D (50%, with limit):** `[O43]= ROUND(MIN(Total_Income,MIN(CDE_EligibleAmount,VALUE(SUM(IF(L43>2000,0,L43),M43)/2))),0)` → half the donation, capped at Total_Income and at the **remaining** qualifying limit `CDE_EligibleAmount`.

**Per-table Total eligible (O):**
- `[O12]= MIN(SUM(Per10080G.EligibleAmt),Total_Income)` (A).
- `[O24]= ROUND(MIN(SUM(PerNO5080G.EligibleAmt),Total_Income),0)` (B).
- `[O36]= ROUND(MIN(C_Eligible,CD_EligibleAmount),0)` (C — total eligible of C, capped at qualifying limit).
- `[O48]= ROUND(MIN(Total_Income,MIN(CDE_EligibleAmount,VALUE(SUM(Per5080G.EligibleAmt)))),0)` (D).

**The qualifying-limit computation (the core of C & D):**
- `Total_Income` = named range `'80G'!$T$5` = `[T5]= hp.IncOfCurYrAfterSetOffBFLosses1 + busipofincl.IncOfCurYrAfterSetOffBFLosses2 + busipofinclspec.IncOfCurYrAfterSetOffBFLosses2a + rh.IncOfCurYrAfterSetOffBFLosses6 + othsrcincl.IncOfCurYrAfterSetOffBFLosses5 + stcg.IncOfCurYrAfterSetOffBFLosses3b + busipofinclspecified.IncOfCurYrAfterSetOffBFLosses2b + SI!H46 + SI!H59` — the total of current-year income after set-off of brought-forward losses across all heads.
- `QualifyingAmount80G` = `'80G'!$X$3` = `[X3]= ROUND(0.1*MAX(0,(Total_Income-(SUM(scvia.Section80GGA_Calc,scvia.Section80GGC_Calc)+SUM('VI-A'!K10:K20)))),0)` — **10% of adjusted total income** = 10% × max(0, Total_Income − (80GGA + 80GGC + other Chapter VI-A deductions K10:K20)).
- `C_Eligible` = `'80G'!$T$3` = `[T3]= SUM(PerYES10080G.EligibleAmt)` — total eligible of table C.
- `D_Eligible` = `'80G'!$V$3` = `[V3]= SUM(Per5080G.EligibleAmt)` — total eligible of table D.
- `CD_EligibleAmount` = `'80G'!$Y$3` = `[Y3]= QualifyingAmount80G` — the qualifying-limit pool available to C+D.
- `CDE_EligibleAmount` = `'80G'!$AA$3` = `[AA3]= MAX(0,ROUND((CD_EligibleAmount-C_Eligible)/2,0))` — the qualifying limit **remaining for table D after table C's 100% eligible has consumed it**, then halved (D is a 50% bucket).
- So the qualifying limit is applied first to C (100%, up to the whole 10% pool), then the leftover feeds D at 50%.

**Grand Total E (row 52) — with regime/return-type guard:**
- `[L52]= ROUND(Per5080G.TotDon100Percent+PerYES10080G.TotDon100Percent+PerNO5080G.TotDon100Percent+Per10080G.TotDon100Percent,0)` → `TotalDonationsUs80GCash` (sum of the four tables' cash totals).
- `[M52]= ROUND(Per5080G.TotOtherDon100Percent+PerYES10080G.TotOtherDon100Percent+PerNO5080G.TotOtherDon100Percent+Per10080G.TotOtherDon100Percent,0)` → `TotalDonationsUs80GOtherMode`.
- `[N52]= IF(MID(sheet1.ReturnFileSec,1,2)="12",0,IF(bacValue=1,0,ROUND(Per5080G.TotBothDon100Percent+PerYES10080G.TotBothDon100Percent+PerNO5080G.TotBothDon100Percent+Per10080G.TotBothDon100Percent,0)))` → `TotalDonationsUs80G` (= Aiii+Biii+Ciii+Diii, rule 606).
- `[O52]= IF(MID(sheet1.ReturnFileSec,1,2)="12",0,IF(bacValue=1,0,MIN(Total_Income,ROUND(Per5080G.TotElig100Percent+PerYES10080G.TotElig100Percent+PerNO5080G.TotElig100Percent+Per10080G.TotElig100Percent,0))))` → `TotalEligibleDonationsUs80G`.
- The guard `MID(sheet1.ReturnFileSec,1,2)="12"` (return filed u/s 12 — trust) **or** `bacValue=1` (new tax regime) forces N52/O52 to **0** — matches rule 610: *"Deduction u/s 80G cannot be claimed if New tax regime is selected (115BAC/115BAD or 115BAE)."*

**Auto-numbering:** `[D8]= D7+1` (D8:D10, D20:D22, D32:D34, D44:D46) — row serial numbers auto-increment.

**Duplicate-PAN detection (hidden helper `X`/`U`/`Z` columns):**
- `[U7]= IF(J7="","",COUNTIF(PerNO5080G.DoneePAN,J7)+COUNTIF(PerYES10080G.DoneePAN,J7)+COUNTIF(Per5080G.DoneePAN,J7))` — counts the same PAN across the *other* three tables.
- `[X7]= IF(L7>0,"Data","NoData")` — flags whether a cash amount is entered.
- These back rule 608: *"PAN of Donee cannot repeat in any one of the set of blocks (i.e 100%, 50%, with Qualifying limit, without Qualifying limit) except for PAN 'AAAAR1077P'"* and VBA messages *"PAN of the donee cannot be repeated. Please enter aggregate amount of donation against donee PAN only once."* / *"Same PAN cannot be entered for \"Donation in cash\" in Schedule 80G."* Note (rule 609): for table D the no-repeat rule does not apply when the ARN number is unique.

### Other validation rules (from rules.json)

- **596** — Donee PAN cannot equal the Assessee PAN or PAN at Verification.
- **597** — Total amount of deduction computed cannot be more than the eligible amount at Sl.no. E.
- **606** — Total at E = Aiii + Biii + Ciii + Diii.
- **607** — If 80G is claimed in Schedule VI-A, donation details must be provided in Schedule 80G.
- **609** — In Schedule VI-A, sl.no.1a system-calculated 80G value must match the eligible donation total (E) in Schedule 80G.
- **611/612** — Transaction Reference number (UPI/Cheque/IMPS/NEFT/RTGS) and/or IFSC code of Bank must be filled for every "contribution in other mode" entry; PAN of donee mandatory when donation amount > 0.
- **4595** — Deduction u/s 80G shall be claimed against valid Donee PANs only.
- **VI-A cross-links (rules 3255/3375 context):** VI-A sl.no.1a "80G" = `TotalEligibleDonationsUs80G` (E/O52); eligible 80G claimed cannot exceed the user-enterable amount.

## What repeats and what is one figure

- **Repeats:** each of the four tables A/B/C/D is a **repeating donee list** (`<Block>.DoneeDetail[]` array). Four donee rows are pre-drawn per table (rows 7–10 / 19–22 / 31–34 / 43–46) with add-row buttons `Button_80G1..Button_80G4` (`[E13]`, `[E25:G26]`, `[E37]`, `[E49]`); the count is not fixed.
- **One figure each:** the four per-table Total rows (A r12, B r24, C r36, D r48), the grand-Total E (r52), and the hidden helper cells `C_Eligible`/`D_Eligible`/`QualifyingAmount80G`/`CD_EligibleAmount`/`CDE_EligibleAmount`.

## Mandatory

- Schedule-level `required`: **`TotalDonationsUs80GCash`, `TotalDonationsUs80GOtherMode`, `TotalDonationsUs80G`, `TotalEligibleDonationsUs80G`**.
- Within each `<Block>`, the four totals are required (e.g. `TotDon100PercentCash`, `TotDon100PercentOtherMode`, `TotDon100Percent`, `TotElgDon100Percent`; and the analogous `TotDon50PercentNoApprReqd*`, `TotDon100PercentApprReqd*`, `TotDon50PercentApprReqd*`).

## What this means for the build

- Build **four donee tables** (A 100% no-limit, B 50% no-limit, C 100% with-limit, D 50% with-limit), each a repeat list mapping to `Don100Percent` / `Don50PercentNoApprReqd` / `Don100PercentApprReqd` / `Don50PercentApprReqd` → `DoneeDetail[]`.
- Per donee row capture: `DoneeName`, `AddressDetail` (AddrDetail, CityOrTownOrDistrict, StateCode dropdown, PinCode), `DoneePAN`, `DonationAmtCash`, `DonationAmtOtherMode`, `TransactionRefNum`, `IFSCCode`, and `ArnNbr` (surface the ARN input for table D). Compute `DonationAmt = Cash + OtherMode`.
- Compute `DonationElgAmt` per table: disallow cash > 2000 in every table; A = min(elig, Total_Income); B = round(min(elig/2, Total_Income)); C = round(min(min(elig, Total_Income), QualifyingAmount80G)); D = round(min(Total_Income, min(CDE_EligibleAmount, elig/2))).
- Implement the **qualifying-limit chain**: `Total_Income` (sum of current-year income after set-off across heads), `QualifyingAmount80G` = 10% × max(0, Total_Income − (80GGA + 80GGC + VI-A K10:K20)); `CD_EligibleAmount = QualifyingAmount80G`; `CDE_EligibleAmount = max(0, round((CD_EligibleAmount − C_Eligible)/2))` — C consumes the 10% pool first, D gets the halved remainder.
- Compute per-table totals (L/M/N/O) and grand-Total E (`TotalDonationsUs80GCash/OtherMode`, `TotalDonationsUs80G`, `TotalEligibleDonationsUs80G`), with the guard that N52/O52 = 0 when the return is filed u/s 12 or the new regime (`bacValue=1`) is chosen.
- Enforce: PAN mandatory when donation > 0; PAN ≠ Assessee/Verification PAN; no duplicate PAN across tables except `AAAAR1077P` (and, for table D, uniqueness excused when ARN is unique); Transaction Ref + IFSC mandatory for other-mode entries (IFSC = 11 chars, 4 alpha + "0" + 6 alnum); "GGGGG0000G" allowed as Government-donee PAN; feed E's eligible total into Schedule VI-A sl.no.1a "80G".
- Populate the State Code dropdown from `StatesWithoutForeign` (37 states, no "99-Foreign"); store the leading 2-digit code.
