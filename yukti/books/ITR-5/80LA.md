## The shape

A single header block (`[C4] Schedule80LA` / `[D4] Deduction in respect of offshore banking unit or IFSC`) over **one repeating table of up to 4 unit rows** (rows 6–9) plus two cross-total cells and a grand-total row.

- Rows **6–9** are the four repeat rows of the table — one per offshore banking / IFSC unit (schema array `Schedule80LADtls[]`).
- Cells **`[S6]` / `[T6]`** (with header labels `[S5] 1. 80LA(1)` / `[T5] 2. 80LA(1A)`) are two computed sub-section subtotals that feed **Schedule VI-A** — they are **not** part of the exported `Schedule80LA` block.
- Row **12** (`[C12] Total`, `[K12]`) is the grand-total of the amount column → schema `Total`.

Per-row dropdowns for **Type of Entity** (col E) and **Type of income of the unit** (col F) are **conditional on the Sub-section chosen in col D** (rules 618/619, see below).

## The rules the sheet computes (with cell references)

1. **Sl.No. auto-increment** — `[C7]= C6+1`, `[C8]= C7+1` (row 6 = 1). Not user-editable.
2. **80LA(1) subtotal** — `[S6]= SUMIF(Subsection_80LA,S5,AmountDedClamied_80LA)` where `S5 = "1. 80LA(1)"`, `Subsection_80LA = '80LA'!$D$6:$D$9`, `AmountDedClamied_80LA = '80LA'!$K$6:$K$9`. Result named `TotalAmountDed_80LA1`.
3. **80LA(1A) subtotal** — `[T6]= SUMIF(Subsection_80LA,T5,AmountDedClamied_80LA)` where `T5 = "2. 80LA(1A)"`. Result named `TotalAmountDed_80LA1A`.
4. **Grand total** — `[K12]= SUM(AmountDedClamied_80LA)` → schema `Total` (must equal S6 + T6).
5. **RegDate lower bound** — schema: `RegDate` must be a `YYYY-MM-DD` date **on or after 2024-04-01**.
6. **Conditional entity dropdown (rule 618, `rules.json` n=618)** — "In schedule 80LA, type of entity should be enabled based on the sub-section under which the deduction is claimed": if Sub-section = 80LA(1) → entity list = `Typeentiey_80LA` (DB!$DX$3:$DX$4); if 80LA(1A) → entity list = `Typeentiey1_80LA` (DB!$DX$6 = "1. A Unit of IFSC"); neutral = `Typeentiey2_80LA` (DB!$DX$5 = "(Select)").
7. **Conditional income dropdown (rule 619, `rules.json` n=619)** — "type of income of the unit should be enabled based on the sub-section": if 80LA(1) → `Typeofincomeunit_80LA` (DB!$DZ$3:$DZ$4); if 80LA(1A) → `Typeofincomeunit1_80LA` (DB!$DZ$5:$DZ$6); neutral = `Typeofincomeunit2_80LA` (DB!$DZ$2 = "(Select)").
8. **Sub-section mandatory when amount entered (rule 616, n=616)** — "Amount of deduction claimed is more than zero but section under which the deduction claimed is not selected."
9. **Full row required when amount entered (rule 617, n=617)** — "Amount of deduction claimed at Sl. No. 8 is more than zero but remaining field at Sl. No. 1 to 7 is not filled up." (Rule text's "Sl. No. 8" = the amount column, which this sheet's header labels "9"; discrepancy noted, header numbering is authoritative for the build.)

## What repeats and what is one figure

- **Repeats:** `Schedule80LADtls[]` — the 4 unit rows 6–9 (Sub-section, Type of entity, Type of income, Authority, Reg date, Reg number, First AY, Amount). Build as an array, max 4 rows in the utility.
- **One figure:** `Total` (`[K12]`, grand total). The two subtotals `[S6]` (`TotalAmountDed_80LA1`) and `[T6]` (`TotalAmountDed_80LA1A`) are single computed helper figures that feed VI-A; not exported inside the `Schedule80LA` block.

## Mandatory

Schema `Schedule80LA` `required: None`; block `required: false` (`blocks.json`) — the whole schedule is optional (built only when a 80LA deduction is claimed). No leaf is individually flagged `required` in the schema.

Utility-enforced conditional mandatories (validation rules, not schema `required`):
- If `AmtDedCurAY` > 0 → `SubSecDedClmd` must be selected (rule 616).
- If `AmtDedCurAY` > 0 → all of cols 1–7 (entity, income, authority, reg date, reg number, first AY) must be filled (rule 617).
- Entity (col E) / income (col F) become enabled only after Sub-section is chosen (rules 618/619).

## What this means for the build

- Build one array widget `Schedule80LADtls[]` with a fixed cap of 4 rows. Sl.No. is auto (1..n), not user input.
- Column D (`SubSecDedClmd`) is the driver: on change, re-populate col E (`EntityType`) and col F (`IncmTypeUnt`) from the sub-section-specific lists (80LA(1) → bank options; 80LA(1A) → IFSC options), and clear any incompatible prior selection. Store the enum **code** (e.g. `SchdBankSEZ`), display the label.
- Validate `RegDate` ≥ 2024-04-01 and format `YYYY-MM-DD`; `RegNumber` ≤ 30 chars; `FstAYDeduction` ≤ 7 chars (AY like `2024-25`); `AmtDedCurAY` integer ≥ 0.
- Compute `Total = SUM(AmtDedCurAY)` (= `[K12]`) and the two helper subtotals `TotalAmountDed_80LA1` (SUMIF sub-section = 80LA(1)) and `TotalAmountDed_80LA1A` (SUMIF sub-section = 80LA(1A)); wire those two into Schedule VI-A rows 18/19 (`scvia.Section80LA`, `scvia.Section80LA1A`).
- Enforce the cross-schedule guards at VI-A / Part A-General: 80LA(1) vs 80LA(1A) mutually exclusive (rule 663); IFSC-in-convertible-FX Yes/No gate (rules 664/665); VI-A claim ≤ Schedule 80LA amount (rules 669/671); Schedule 80LA must be filled if VI-A claims it (rules 670/672); Form 10CCF must be filed to allow the deduction (category-B rule 3); 80LA(1A) blocked under 115BAD/115BAE/115BAC(1A) (rule 19).
- Only the `Schedule80LA` block (`Schedule80LADtls[]` + `Total`) is exported here; the S/T subtotal cells are internal helpers.
