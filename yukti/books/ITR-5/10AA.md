## The rules the sheet computes (with cell references)

- **Auto serial number** — `[G6]= G5+1`, `[G7]= G6+1`, `[G8]= G7+1`, `[G9]= G8+1`, `[G10]= G9+1` → undertaking numbers 1..5 (display only, not stored).
- **Total = sum of per-row amounts, ZEROED under new tax regime** — `[J11]= IF(bacValue=1,0,SUM(AA10.DedFromUndertaking))`. So `TotalDedUs10Sub = 0` when `bacValue = 1` (new tax regime u/s 115BAC), else `= SUM(DedUs10Sub over the 5 rows)`. This is the **deduction cap/gate**: no 10AA deduction is allowed in the new regime. Matches rules.json **A580**: *"In 'Schedule 10AA', value at field 'Total deduction under section 10AA' should be equal to the sum of values at all rows."*
- **Applicability flag** — `[L14]= IF(bacValue=1,0,1)` → 1 when the schedule is applicable (old regime), 0 under the new regime.
- **First-row precedence** — `[F3]` note: *"If no entry is made in first row then other rows will not be considered."* The five rows must be filled top-down; row 1 (undertaking No.1) is the anchor.

### Cross-schedule rules (from rules.json)
- **A799**: *"If Deduction u/s 10AA is claimed in Part B TI at sl.no.12 then Schedule 10AA should be filled."*
- **A804**: *"In schedule part BTI - Deduction u/s 10AA at sl.no.12 cannot be more than deduction claimed in schedule 10AA."* (Part B-TI 10AA ≤ `TotalDedUs10Sub`.)
- **A679**: *"In Schedule AMT, Sl.no. 2b … total deduction under section 10AA at sl.no.12a of Part BTI"* — AMT add-back 2b = 10AA deduction. (Named range `AMT.DeductClaimSec10AA` = `AMT!$H$7`.)
- **B18** (cat B): *"Assessee claiming deduction u/s 10AA is required to file ITR within due date."*
- **B26** (cat B): *"Deduction u/s 10AA is claimed in the Income Tax Return only if Form 56F is filed."*
- Feeds Part B-TI: named range `Sheet8b.DeductionsUnder10Aor10AA` = `'PARTB - TI - TTI'!$L$44`.

## What repeats and what is one figure

- **Repeats:** the undertaking row (AY + amount) is an array `DedFromUndertakingWithAy[]`, up to **5 fixed rows** (undertaking No.1..5); schema `minItems: 1`. The Undertaking label column is pre-printed, not a per-row input.
- **One figure:** `TotalDedUs10Sub` (`J11`) — single computed total. The `bacValue` regime flag and `L14` applicability flag are single figures.

## Mandatory

- Block schema `required: ['DeductSEZ']`; `DeductSEZ.required: ['DedUs10Detail']`; `DedUs10Detail.required: ['Undertaking','TotalDedUs10Sub']`; each array item `required: ['AssmtYrUnit','DedUs10Sub']`. `AssmtYrUnit` also carries `nonEmptyString`.
- In practice the whole schedule is **conditional**: fill only when a 10AA deduction is claimed. If claimed (Part B-TI sl.12 > 0), Schedule 10AA must be filled (A799) with at least one undertaking row (`minItems: 1`), and the AY + amount of that row are mandatory. Requires timely ITR (B18) and Form 56F (B26); also feeds Schedule DI sl "B".

## What this means for the build

- Build a fixed **5-row grid** (Undertaking No.1..5, labels pre-printed) with two inputs per row: **Assessment year** (dropdown, the 18 AY values 2005-06 … 2022-23) → `AssmtYrUnit`, and **Amount of deduction** (integer ≥ 0) → `DedUs10Sub`. No add/remove control beyond the 5 fixed rows.
- Emit the array `DeductSEZ.DedUs10Detail.Undertaking.DedFromUndertakingWithAy[]` in row order, skipping empty rows but keeping row 1 as the anchor (empty first row ⇒ later rows ignored, per `[F3]`).
- Compute `TotalDedUs10Sub` (`J11`) = `IF(new regime, 0, SUM(DedUs10Sub))`. **Wire the new-regime gate:** when `bacValue = 1` (115BAC opted, not opted out) the total is 0 and the schedule is effectively disabled (`L14 = 0`).
- Do not build a schema key for the undertaking name; the F column is a fixed label and the undertaking is identified by array index.
- Cross-wire: Part B-TI sl.12 (`PARTB - TI - TTI`!L44) ≤ `TotalDedUs10Sub` (A804); AMT 2b add-back = 10AA deduction (A679).
- Enforce/notice: claiming 10AA requires ITR within due date (B18) and Form 56F filed (B26); prompt to fill Schedule DI sl "B" (hidden note row 12).
- Populate one value-list dropdown (H6:H10, `ayunit23_24`). Row 12 (H) not built.
