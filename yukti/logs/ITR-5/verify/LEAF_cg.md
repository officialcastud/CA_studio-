## Other defects found while tracing (not coverage gaps)

These leaves **do** have a home, so they are not ORPHANs, but the home is wrong. Reported here because the CEO is fixing this file anyway.

1. **Free text against a closed enum — exports an invalid return.** `TrnsfImmblPrprtyDtls[].CountryCode` (data-p `cg.land.<i>.pcountry`, `inp(...,{max:4,ph:"91"})` L418) and `NRIDTAADtls[].CountryCodeExcludingIndia` (data-p `cg.a9|b11.<k>.ccode`, `{max:5}` L516) are plain text boxes, but the schema pins both to the closed ITD country-code enum (~240 values, `91`, `2`, `1` …, `9999`). Reproduced: entering the ISO code `840` for the USA (ITD's code is `2`) makes `Draft4Validator` reject the return at `…/TrnsfImmblPrprtyDtls/0/CountryCode` and `…/NRIDTAADtls/0/CountryCodeExcludingIndia`. These should be `sel()`s over the schema enum (the form already has a country list — `CG_STATE` is built the same way).
2. **`EditAutopoulatedDetail` can only ever be `"Y"`.** `sel("cg.editE",[["false","No"],["true","Yes"]])` (L716) stores the **string** `"false"`, which is truthy, so `if(st0(C.editE?"Y":"")||C.editE)CG.EditAutopoulatedDetail=C.editE?"Y":"N";` (L954) yields `"Y"` whenever the user has touched the control, and `"N"` is unreachable. `cgOn()` (L239) shows the author knows `<select>` stores strings; `editE`/`editF` were missed.
3. **The set-off override the form offers cannot be made.** `engCg` L323 honours `C.Eover`, but no `data-p` anywhere writes `S.cg.Eover` — `setoffTable()` L466-474 renders read-only `cell()`s. So answering "Edit the auto-populated set-off? = Yes" flags `EditAutopoulatedDetail="Y"` on a matrix the user could not edit. (The Part F twin *does* work: `quartersTable()` L484 renders real `cg.Fover.*` inputs.)
4. **`quartersTable` edit-gate has the same truthiness bug.** `const ed=!!S.cg.editF;` (L479) — `"false"` is truthy, so the quarter boxes become editable after choosing *No*. Harmless in effect (`F[k]=(C.editF&&ov)?…` L347 has the same bug consistently) but wrong.
