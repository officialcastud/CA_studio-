# ITR-4 · Category A rules 351–400 — enforcement audit
read-only · opus auditor

Key structural facts established while auditing this slice:
- **Exempt income (D20)** is a repeatable table whose sub-category (`sub` → `SubCategory`) is a **free-text field**, not a dropdown (70_sec_inccore.js:586). Dedup ("cannot be selected more than once") is only enforced where an explicit `A(n, cntSub("<code>")<=1)` exists (70_sec_inccore.js exempt block; helper `cntSub` at 61_rules_g0.js:26). Only 7 of the ~24 codes in this slice are covered; the rest are unenforced holes.
- **Form 10-IEA (A23)** is implemented in a *simplified* Sugam form: it models A23 (`f10ieaEarlier`), A23(A)(i) (`f10ieaAY`/`f10ieaAck`), A23(B) (`optout`→`F10IEACurrAYOldRegime`) and A23(B)(i) (`f10ieaDateCur`/`f10ieaAckCur`) at 70_sec_inccore.js:411-421. The entire **A23(A)(ii) re-entry sub-tree** — A23(A)(ii), (ii)(a), (ii)(b), (ii)(b)(i) — is **not modeled**, so rules keyed on it are either unenforceable holes (forward mandates) or vacuously satisfied (reverse-consistency).
- **234-I revised-return fee** (`fee234i`) and **234F fee** are plain user inputs capped at ₹5,000 (70_sec_inccore.js:697-698); no rule ties them to filing date / section / income.
